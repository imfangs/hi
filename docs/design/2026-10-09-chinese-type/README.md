# Hi 中文字体：研究、取舍与实施

日期：2026-10-09。用户要求先研究业界声音，再判断、优化并上线。决定采用 **宋体标题＋黑体说明与正文**。这是一项结合Hi内容、实际对照的设计判断，不是字体类别的普遍优劣结论。

## 对照与取舍

[同内容三栏对照](comparison.html)保持字号、行高、宽度和文字相同，比较全宋/全黑/混排。字体均实际加载；受控截图见 comparison.jpg。

- 全宋：文字整体更像文章页，标题与说明的语气区分较弱。
- 全黑：清楚直接，但Hi标题更接近一般产品界面，与已有Instrument Serif口号的联系变弱。
- 混排（采用）：作品名与章节标题保留宋体的笔画变化，说明与操作使用平实黑体。更适合既有作品展陈和阅读详情。

以上为本轮视觉判断；用户最终品味反馈仍是后续依据。未改英文口号、六种Shader、作品顺序、原媒体或内容。

## 发现的真实问题

旧 `noto-serif-sc-subset.woff2` 的cmap只有307字符。修改前源码有905个不同汉字，612个不在该文件，依赖系统回退；不是说612个用户可见字一定都是方框。旧文件有200–900可变字重，并非只有一种粗细。真正问题是覆盖与跨设备一致性。

新子集包含当前src中的909个汉字、ASCII和常用标点。两套都由固定Google Fonts提交 `2eb0b48d5f760f62e286216f0859a8c540dbc1bd` 的原始字体生成，自托管WOFF2，保留400–600变量轴与OFL。修改子集内部家族名为Hi Song/Hi Sans，CSS仍回退到系统字体。

- Hi Song：Noto Serif SC，作品名、详情标题、关于标题；通常500。
- Hi Sans：Noto Sans SC，作品说明、详情正文、导航/按钮；通常400，强调600。英文工具文字继续Geist。
- 正文桌面17px/1.9、手机16px/1.9；手机作品说明由14px增至15px。去掉正文额外字距，避免中文长段落被无必要地拉散；标题字距收敛。
- 两个中文子集合计619656bytes（约605KiB），较原单一小子集增加下载量，以换取全站覆盖。`font-display:swap`保留先读系统字的路径，没有预加载全字库。此成本明确保留，未宣称性能免费提升。

## 维护与验证

`pnpm fonts:build`使用uv临时环境运行fontTools/Brotli，从固定来源缓存字体，生成WOFF2和 `scripts/font-manifest.json`；先子集化再收窄变量轴，避免先处理全字库的高成本及本轮工具错误。生成后独立重开字体检查cmap。`pnpm build`先运行 `scripts/check-fonts.mjs`，核验文件哈希及新源码字是否被覆盖；新增内容缺字会报错，不再无声遗漏。这个检查证明静态src字集，用户自由输入仍用系统回退。

浏览器CSS平台字体接口回读：作品标题4字使用自托管Hi Song，说明19字使用自托管Hi Sans，避免只凭CSS声明判断字体已生效。

桌面1280和手机390两个视口逐个打开17个详情，标题与布局正常、无横溢；有src的已完成图片无破图。漫画页有一个无src的非内容img，最初统计误报后单独核实，未当作字体回归修复。深色正文、中文标点和宋黑层级已受控看图；真实手机/Safari/持续阅读感受未验证。
